### [OpenJDK 曝 Java4Shell 高危远程代码执行漏洞](https://calif.io/java4shell/) ⭐️ 8.0/10

一篇详细分析披露了被称作 Java4Shell 的 OpenJDK 远程代码执行漏洞 CVE-2026-114938，CVSS 4.0 评分 9.2，称其无需认证且已潜伏近四年。受影响版本包括 Java 17（17.0.6 及之后所有 17 系列版本）、21、25 和 27；标准 Java 8/11 通常不受影响，但 Oracle Java 8 Performance Pack 例外。漏洞仅在支持 AVX-512 VBMI 的 x86-64 服务器处理器上触发，大致对应 2021 年及以后发布的 Intel Ice Lake 及更新 Xeon、2022 年及以后发布的 AMD Zen 4 及更新 EPYC/Ryzen，ARM64 不受影响。攻击针对 Base64 处理路径并涉及远程堆布局，实际利用对网络 RTT 和抖动敏感。

hackernews · werrett · 11月17日 21:11 · [社区讨论](https://news.ycombinator.com/item?id=50538240)

**「背景」** 该漏洞位于 HotSpot 的 Base64 解码路径：在支持 AVX-512 VBMI 的 x86-64 机器上，JIT 编译器会为 Base64 解码生成一条向量化 stub，缺陷出在这段解码代码的内存处理上，可造成堆破坏（tool-2-2、tool-2-3）。多家安全厂商的初步分析还指出，除远程代码执行外，该缺陷也可被用于未认证的拒绝服务攻击；评分上，研究者按 CVSS v4.0 给出 9.2，Oracle 按 CVSS v3 给出 8.1（tool-2-1、tool-2-2）。

**「影响」** 对受影响环境而言，攻击可靠性高度依赖低且稳定的网络往返时延，远程堆布局在抖动较大的链路上更难稳定成功，因此并非所有满足版本和 CPU 条件的实例都可被同等可靠地利用。Semgrep 已发布针对该 CVE 的免费检测脚本，重点检查 HotSpot VM（OpenJDK、Oracle JDK 或 GraalVM JDK）等五项条件；社区还提出以 -XX:UseAVX=2 规避 AVX-512 路径，但该说法尚未得到确认。

**「社区讨论」** 评论普遍认可这项研究的难度，但同时指出利用条件具体且对 RTT/抖动敏感，远程堆布局在低且稳定的往返时延下才更可靠，因此实际影响范围仍受网络条件限制。Semgrep 团队表示已发布覆盖 HotSpot VM 等五项条件的免费检测脚本；另有评论转述未经证实的说法，称可通过 -XX:UseAVX=2 规避 AVX-512 的 Base64 解码路径。

### [OpenAI 发布 GPT-6.2 Astra 与 Sol](https://openai.com/index/introducing-gpt-6-2-astra-sol/) ⭐️ 8.0/10

OpenAI 发布 GPT‑6.2 Astra 和 GPT‑6.2 Sol，分别面向高难度项目与日常工作，API 名为 \`gpt-6.2-astra\` 和 \`gpt-6.2-sol\`。Astra 定价为每百万 token 输入 8 美元、输出 40 美元，是上一代 GPT-6 Astra（10/50 美元）的 80%，缓存输入从每百万 token 1 美元降至 0.40 美元；Sol 维持 6.1 Sol 的 2/10 美元。Simon Willison 的对比测试称，两模型生成“Yonkers 变机甲”动画的效果都不如 Claude Fable 5.2 和 Gemini 4 Carbon，且 Astra 在多项基准上低于 Fable 5.2。

hackernews · jasondavies · 11月17日 17:46 · [社区讨论](https://news.ycombinator.com/item?id=50535230)

**「背景」** OpenAI 的模型线近年分为两类：Astra 面向最困难的前沿任务，Sol 定位高效、通用的日常模型。上一代 GPT-6 Astra 的 API 价格为每百万 token 输入 10 美元、输出 50 美元，与 Claude Fable 5 相同；GPT-6.1 Sol 与 GPT-6 Sol 则维持每百万 token 2 美元／10 美元，是 GPT-5.6 Sol（4 美元／20 美元）的一半。因此 6.2 Astra 的 8 美元／40 美元和 0.40 美元／百万 token 的缓存价格，是在既有价位上再降一档，而非首次调价。

**「对开发者的影响」** 对 API 开发者而言，Astra 的缓存输入降价会直接压低长时 agentic 会话中重复上下文的成本；使用 LLM 工具的用户需升级到 0.38 才能选用这两个模型。

**「社区讨论」** 评论者 chriddyp 报告，在自家数据分析考试中 Astra 成本从约 20 美元降至约 4 美元、Sol 从 2.6 美元降至 1.2 美元，准确率相近，并将部分降幅归因于 token 用量和工具调用减少，但也提到模型有时“提前完成”而未找到目标答案。Topfi 则批评 OpenAI 展示的 Slideshow、Workbook 和备忘录示例质量差，认为办公室工作仍非其强项。

### [Datasette Lite 用 Service Worker 重写为浏览器内完整应用](https://simonwillison.net/2026/Nov/17/datasette-lite/) ⭐️ 8.0/10

Simon Willison 发布了 Datasette Lite 的完整重写版：它通过 Service Worker 与 Pyodide/WebAssembly，在 lite.datasette.io 的浏览器页面中运行完整的服务端 Datasette Python 应用。用户可以用 URL 参数加载 SQLite 数据库、JSON、CSV 或 SQL 脚本，从 PyPI 选择已发布的 Datasette 版本，从 GitHub 加载指定 commit、tag 或分支，并在 100 多个 SQLite 版本中选择。用户还可以通过 ?install= 从 PyPI 或 wheel URL 安装 Datasette 插件；加载远程数据库的 URL 需要提供开放 CORS 头。作者称新版本与真实服务器端应用几乎无法区分。

rss · Simon Willison · 11月17日 16:48

**「背景」** Datasette Lite 最早于 2022 年推出，原实现是在 Pyodide Web Worker 中模拟请求，再用 innerHTML 将结果 HTML 注入顶层页面；这导致依赖 JavaScript 的功能无法运行，也限制了插件加载。

**「影响」** 对 Datasette 开发者和插件作者而言，现在可以用一条可分享的 URL 固定 Datasette 版本、SQLite 版本、数据文件和插件，以复现 bug 或演示未发布功能；作者已用 ?ref=1.0a42 和 ?ref=1.0a43 的链接对比分页 bug 的旧行为与修复结果。

### [Optimizely 签名脚本被篡改，178 个网站分发恶意代码](https://arstechnica.com/security/2026/11/malicious-code-delivered-through-optimizely-hits-visitors-to-hundreds-of-sites/) ⭐️ 8.0/10

ReportURI 周二表示，使用 Optimizely 的 178 个网站——包括 CNN、Zoom、BBC 和 Salesforce——被植入恶意 JavaScript，并向访客分发多种载荷。攻击者修改了由 Optimizely 数字签名、从 cdn.optimizely.com 分发的客户脚本片段；这些脚本运行在相关网站的每个页面上。研究人员称，载荷会替换加密货币钱包地址、窃取支付卡数据、Cookie 和截图，并针对 iPhone 和 iPad 投递名为 Coruna 和 DarkSword 的 iOS 漏洞利用套件。上述发现来自 ReportURI，事件细节和受影响范围尚未见独立确认。

rss · Ars Technica · 11月17日 22:32

**「背景」** Optimizely 向客户站点提供的是在每个页面加载的第三方 JavaScript「snippet」，其中混合了平台自身代码和客户自定义代码，并可由 cdn.optimizely.com 直接下发；正因如此，这段脚本一旦被写入恶意代码、又带着该域名的有效证书签名，影响范围就会自动覆盖所有接入的站点。此次投递的两个 iOS 漏洞利用套件此前已有公开记录：据相关条目记载，Google 威胁情报小组于 2026 年 3 月 3 日披露了包含 23 个漏洞的 Coruna，iVerify 随后报告了针对较新 iOS 版本（18.4–18.7）的 DarkSword，后者还被用于针对乌克兰目标的水坑攻击。

**「直接影响」** 对使用 Optimizely 的网站运营者来说，直接后果是必须把 cdn.optimizely.com 上经其签名分发的客户脚本视为可能已被篡改：在清理并重新验证前，应停用受影响片段，并排查支付页、登录会话和加密钱包相关交互是否出现异常。

### [编码代理的外部沙箱模式及三种实现](https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/) ⭐️ 7.0/10

Simon Willison 与 Prime Radiant 介绍了一种“外部沙箱”模式：编码代理本身运行在沙箱之外，而代理要求执行的代码被放进专用沙箱，以降低提示注入或本地模型误操作对主机造成破坏的风险。该项目发布了三个使用同一 localhost API 的沙箱服务器实现：基于 Node.js 与 v86、在 WebAssembly 中运行 Alpine Linux 的 external-sandbox-v86，基于 Python 与 Apple Containers 的 external-sandbox-container，以及基于 Python 和微软 Quicksand（打包 QEMU 与 Alpine Linux）的 external-sandbox-quicksand。用户可配置 Pi、Claude Code 或 Codex，在需要执行代码时调用该 API；沙箱还提供可选的 HTTP/HTTPS 主机允许列表代理，以及在不向代理暴露密钥的情况下替换凭据的机制，并支持在运行中通过界面调整代理策略。
