telegram · zaihuapd · 11月19日 02:00

### [Nginx HTTP/2 被曝未认证远程代码执行漏洞](https://www.wiz.io/blog/nginx-http2-rce-vulnerabilities) ⭐️ 8.0/10

Wiz 博客报道称，Nginx 的 HTTP/2 处理存在未认证远程代码执行漏洞，源材料附带的 CVE 记录为 CVE-2026-123633 和 CVE-2026-123007，受影响的是启用 HTTP/2 的 Nginx 部署。评论者指出 HTTP/2 并非 Nginx 默认开启，目前约 12% 的服务器启用；有人称实际利用需要约 128GB 的 HTTP/2 流量和特定 CPU 指令，因此危害受条件限制。还有评论称修复已在一周前进入开源仓库，并质疑为何未更早发布禁用 HTTP/2 的临时公告；官方修复版本和完整影响范围在现有材料中尚不明确。

hackernews · speedping · 11月18日 15:19 · [社区讨论](https://news.ycombinator.com/item?id=50547374)

**「背景」** NGINX 的 HTTP/2 支持在标准配置中默认关闭，但在 ingress-nginx 等部分部署中默认开启，因此受影响范围取决于是否启用了 HTTP/2。此次披露对应 CVE-2026-123633 和 CVE-2026-123007 两个 HTTP/2 远程代码执行漏洞；其中 CVE-2026-123633 是在将 HTTP/2 客户端连接代理到后端时触发的释放后使用（use-after-free）问题，F5 已于 2026 年 11 月 18 日发布修复。

**「影响与处置」** 使用 HTTP/2 的 NGINX 部署，尤其是把 HTTP/2 客户端连接代理到后端的配置，会暴露于该 use-after-free 缺陷：Red Hat 称成功利用可导致任意代码执行，或使 worker 进程崩溃造成拒绝服务。运维方应优先升级到 F5 提供的修复版本；F5 按 CVSS 3.1 给每个 CVE 评 8.1（High），按 CVSS 4.0 评 9.2（Critical），且 NGINX Plus 的补丁路径与开源版不同，需按对应版本处理。

**「社区讨论」** 评论区的核心分歧在严重性：一方认为 HTTP/2 默认未启用、启用比例仅约 12%，且据称利用门槛包括约 128GB 流量和特定 CPU 指令，因而称其为“非问题”；另一方则批评修复提交提前一周出现在开源仓库，认为应更早向用户发布禁用 HTTP/2 的临时指引。

### [Java4Shell 漏洞可致多个企业 Java 应用远程代码执行](https://www.solidot.org/story?sid=85923) ⭐️ 8.0/10

一个名为 Java4Shell 的高危漏洞被公开，该漏洞被指源于 OpenJDK Base64 解码器的内存损坏问题，CVSS 4.0 评分为 9.2/10。报道称，Keycloak、Jira、Confluence、JFrog、Jenkins 和 PingFederate 会出现无需身份验证的远程代码执行，而 Apache Kafka、Solr、ElasticSearch、Gerrit 和 Netflix Spinnaker 则是在身份验证后触发远程代码执行。当前材料没有给出 CVE 编号、受影响版本、利用状态或缓解措施，因此上述影响范围与严重性仍属报道中的说法，尚无法独立核验。

rss · Solidot · 11月18日 13:27

**「背景」** 该漏洞已分配编号 CVE-2026-114938，是 OpenJDK Base64 解码器中的堆溢出，问题出在 Java 运行时面向 x86-64 处理器的优化解码实现。发现该漏洞的研究者按 CVSS 4.0 给出 9.2 分，Oracle 则按 CVSS 3.1 给出 8.1 分，两者采用的评分标准和评分主体不同。

**「影响」** 对运行上述应用的组织而言，Keycloak、Jira 等无需认证即可触发的情形直接扩大了暴露面，而 Kafka、Solr 等则需要先通过身份验证才能利用。由于材料未说明受影响 OpenJDK 版本和修复版本，运维方目前无法仅凭该报道判断现有部署是否受影响或已修复。

### [Optimizely 遭入侵：恶意脚本波及至少 178 家网站](https://www.solidot.org/story?sid=85920) ⭐️ 8.0/10

用于网页 A/B 测试的第三方服务 Optimizely 遭入侵，攻击者通过被称为 OPTIMJACK 的漏洞，向至少 178 个客户网站的项目中注入恶意 JavaScript，使访客在浏览页面时被植入恶意程序。受影响网站包括 BBC、CNN、Zoom、宜家、Salesforce、汇丰银行和 TalkTalk 等。攻击者投放了多种恶意负荷：把用户加密货币钱包地址替换为攻击者控制的地址，窃取支付卡信息、Cookie 和屏幕截图，并利用旧版本 iOS 的漏洞攻击 iPhone 和 iPad。Optimizely 表示已修复漏洞并通知受影响客户，但目前不清楚有多少设备被安装了恶意程序。

rss · Solidot · 11月18日 09:12

**「背景」** Optimizely 的 Web Experimentation 是一种第三方实验与 A/B 测试服务，网站只需在页面中嵌入其脚本，即可在不修改底层代码的情况下调整页面内容和布局。正因为这段脚本由外部服务统一提供并在访客浏览器中执行，一旦供应方被攻破，攻击者便能借助客户站点已有的信任关系，把代码同时推送到所有接入该服务的站点。此次事件中被利用的漏洞被命名为 OPTIMJACK。

**「影响与处置」** 对访问过至少 178 个受影响站点中任一站的用户而言，恶意脚本可能在页面内直接执行，导致加密钱包地址被替换、支付卡信息与 Cookie 被窃取，运行旧版 iOS 的 iPhone 和 iPad 还面临被进一步利用的风险；目前感染设备数量仍不明确。对使用 Optimizely Web Experimentation 的站点，这意味着第三方实验脚本是可直接触达访客的供应链入口，应按 Optimizely 的通知排查项目脚本和访客数据暴露情况，而不是只等待平台修复。

### [Xint 披露 NGINX2Root：五个漏洞可提权至主机 root](https://nginx2root.com/) ⭐️ 8.0/10

据 Xint 披露，NGINX2Root 把 5 个 nginx 漏洞与 1 个 Linux 内核缺陷串联起来，攻击者可从 nginx 访客权限一路提升到主机 root 权限；其中 CVE-2026-123007 被描述为 HTTP/2 流控内存破坏，未认证即可在 worker 中执行命令。nginx 1.30.7 和 1.31.9 已于 11 月 18 日修复 10 个 CVE，Rapid7 已发布 PoC，目前暂无在野利用报告；无法升级的环境应关闭对外 HTTP/2。上述信息来自一条 Telegram 转述，尚缺独立技术验证，且 CVE-2026-123007 的编号也不常见，应视为待核实的披露。

telegram · zaihuapd · 11月18日 16:21

**「背景」** Xint 所称的 NGINX2Root 不是单一漏洞，而是 5 个 nginx 漏洞与 1 个 Linux 内核缺陷的组合；该内核缺陷可与任一 nginx 漏洞串联，把攻击者从 nginx 进程中的执行位置提升到主机 root。F5 在 2026 年 11 月 18 日发布了对这 5 个 nginx 漏洞的修复；同一批更新中，nginx 1.30.7 和 1.31.9 共修复 10 个 CVE。

**「影响与应对」** 暴露 HTTP/2 的 nginx 部署应尽快升级到 1.30.7 或 1.31.9；如果无法立即升级，就应关闭对外的 HTTP/2 监听，以缩小未认证攻击面。公开 PoC 已经出现，而 OpenResty 等下游项目仍在请求同步这两个 nginx 版本的修复；因此，使用下游发行版的团队需要确认其是否已跟进修复，不能只凭上游版本号就判断风险已经消除。

### [从 4004 到 486：x86 早期处理器技术史回顾](https://pikuma.com/blog/history-of-x86-4004-to-486) ⭐️ 7.0/10

一篇发布在 pikuma.com 的技术长文面向对计算机体系结构和复古计算感兴趣的读者，按时间顺序回顾 Intel 从 4004 到 486 的早期 x86 处理器，重点在架构演进与历史脉络，而不是新硬件、新版本或性能评测。文章在 Hacker News 上引发讨论，读者围绕小端序的起源、8008 指令集的作者归属以及 4004 与 8008 的关系提出补充和纠正。由于原文内容没有随该条目一起提供，以上范围主要来自文章摘要与评论，无法独立核实文中全部技术细节。

hackernews · ibobev · 11月18日 14:47 · [社区讨论](https://news.ycombinator.com/item?id=50546967)

**「背景」** 这篇综述把 x86 的谱系上溯到 1971 年 11 月 15 日发布的 Intel 4004；它是 Intel 第一款微处理器，当时售价 60 美元。文章覆盖到 486：它在 i386 架构上加入流水线执行与片上缓存，保持对早期 x86 软件的二进制兼容，并成为首个晶体管数超过一百万的 x86 芯片。文章强调，x86 的架构不是一次设计完成，而是在兼容性约束下逐步累积出来的。

**「影响」** 对学习底层开发的读者，这篇综述可作为理解早期 x86 架构连续性的参考资料；它不涉及当前产品变更，因此没有升级、迁移或兼容性动作可执行。

**「社区讨论」** 评论者认可文章的价值，但提出了多项技术修正：小端序最初是为了提升 2200 的数据访问速度，并非为了算术运算；8008 的指令集虽然并非由 Intel 从零设计，但 Intel 工程师（如 Stan Mazor）确实对它做了增改；4004 与 8008 除了有人员重合外，并无直接关系。另有评论者回忆从 8088 上的 GW-BASIC、A86 汇编到 Turbo Pascal 的编程经历，并称 80386 的 32 位线性内存模型让桌面上的“严肃计算”成为可能。
