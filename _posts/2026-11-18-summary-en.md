### [Java4Shell: OpenJDK Base64 RCE reported on AVX-512 x86-64 hosts](https://calif.io/java4shell/) ⭐️ 8.0/10

A detailed write-up describes Java4Shell, tracked as CVE-2026-114938, an unauthenticated remote code execution flaw in OpenJDK&\#x27;s Base64 processing with a CVSS 4.0 score of 9.2. The report says it affects Java 17.0.6 and later on the 17 line, plus Java 21, 25, and 27, but only on x86-64 processors with AVX-512 VBMI—roughly Intel Ice Lake and newer Xeon, and AMD Zen 4 and newer—while standard Java 8/11 and ARM64 are generally unaffected; Oracle Java 8 Performance Pack is an exception. Exploitation involves remote heap grooming and is described as sensitive to RTT and jitter, with low, stable latency preferred for reliability, so the conditions are narrow but not laboratory-only.

hackernews · werrett · Nov 17, 21:11 · [Discussion](https://news.ycombinator.com/item?id=50538240)

**「Background」** Java4Shell \(CVE-2026-114938\) is a heap overflow in HotSpot’s AVX-512-accelerated Base64 decoder, so the vulnerable code path is reached only on x86-64 processors with AVX-512 VBMI—roughly Intel Ice Lake and later Xeon, and AMD Zen 4 and later—while ARM64 systems are outside it. That hardware-specific decoder is why the flaw affects Java 17.0.6 and later 17 releases, plus 21, 25, and 27, but generally not standard Java 8/11 builds; Oracle’s Java 8 Performance Pack is the noted exception.

**「Impact」** Organizations running affected JDK builds on AVX-512-capable x86-64 servers should determine whether internet-facing services exercise the vulnerable Base64 path and prioritize remediation; ARM64 and standard Java 8/11 deployments can be deprioritized, but Oracle Java 8 Performance Pack cannot. A commenter relays an unconfirmed workaround, -XX:UseAVX=2, that should be treated as a stopgap to verify rather than a fix.

**「Community discussion」** Commenters focused on exploitability and detection: lucasluitjes noted that the remote heap grooming is sensitive to RTT and jitter, though the researchers reported testing over public internet addresses rather than only a lab, and ievans said Semgrep published detection scripts for HotSpot-based OpenJDK, Oracle JDK, and GraalVM while excluding OpenJ9, GCJ, and Azul Prime. AgentME relayed an unconfirmed suggestion that the flaw lies in AVX-512 Base64 decoding and that -XX:UseAVX=2 may work around it.

### [Datasette Lite runs full Datasette app in-browser via service workers and Pyodide](https://simonwillison.net/2026/Nov/17/datasette-lite/) ⭐️ 8.0/10

Simon Willison has released a complete rewrite of Datasette Lite that uses service workers and Pyodide to run the server-side Datasette Python application in the browser, which he describes as almost indistinguishable from the real server-side application. Crafted URLs to lite.datasette.io can load a released Datasette version from PyPI or a specific GitHub commit, tag, or branch; select from over 100 SQLite versions; and install Datasette plugins from PyPI or wheel URLs, including JavaScript visualization tools. The page can also load SQLite databases, JSON files, CSV files, and SQL scripts. Remote database and metadata URLs must have open CORS headers.

rss · Simon Willison · Nov 17, 16:48

**「Background」** Datasette Lite first launched in 2022 as a Pyodide port of Datasette. That version simulated requests in a Pyodide web worker and injected the resulting HTML into the top-level page using innerHTML, which meant features relying on JavaScript in script tags did not execute. The rewrite replaces that approach with service workers.

**「Impact」** Developers can link directly to a specific Datasette build and dataset, allowing a bug reproduction or work-in-progress demo to run without spinning up a web server; Willison demonstrates this by linking Datasette 1.0a42 and 1.0a43 to show a pagination fix. For remote database or metadata files, the hosting server must supply open CORS headers, which is why the example uses GitHub Gists.

### [Optimizely-signed JavaScript served malware on 178 sites](https://arstechnica.com/security/2026/11/malicious-code-delivered-through-optimizely-hits-visitors-to-hundreds-of-sites/) ⭐️ 8.0/10

ReportURI said it identified 178 websites, including CNN, Zoom, the BBC, and Salesforce, that used Optimizely to serve malicious JavaScript to visitors. The code was digitally signed by Optimizely and delivered from cdn.optimizely.com with a valid certificate for that domain, after attackers wrote their code into a portion of each affected customer&\#x27;s JavaScript. The payload swapped cryptocurrency wallet addresses, skimmed payment card data, stole cookies and screenshots, and delivered iOS exploit kits called Coruna and DarkSword to iPhones and iPads.

rss · Ars Technica · Nov 17, 22:32

**「Background」** Sites commonly embed third-party JavaScript—such as Optimizely&\#x27;s personalization snippets—that executes on every page, so tampering at the vendor or its CDN can become a supply-chain compromise across all customer sites. The iOS exploit kits named in the incident predate it: Google&\#x27;s Threat Intelligence Group disclosed the 23-exploit Coruna kit on March 3, 2026, and iVerify later reported DarkSword targeting iOS 18.4–18.7 in watering-hole attacks.

**「Impact」** Visitors to the affected sites faced wallet-address substitution, card skimming, session and screenshot theft, and iOS exploit delivery, while site operators could not rely on the Optimizely CDN domain or its valid TLS certificate to distinguish the malicious code.

The rule is weight perturbation, which the author associates with Williams&\#x27;s 1992 REINFORCE: each trial starts with a random jitter, the agent runs 500 timesteps, and the average light received is compared with a running baseline, so the update scales as learning rate × jitter × \(R − R̄\), reinforcing good wiggles and reversing bad ones. Averaged over hundreds of randomly initialized agents, the noisy paths smooth into a flow map converging on a single &quot;love light&quot; attractor, while individuals pass through recognizable stages — stuck, meandering, avoiding, overshooting, expert — sometimes only after thousands of trials. Change the payoff and the same wiring learns to flee, freeze, or charge; the author likens this to birdsong learning, dopaminergic reward prediction error, and RLHF, scaling from three parameters to a human brain&\#x27;s roughly 86 billion neurons.

**「Takeaway」** The author&\#x27;s thesis is that learning is not the execution of a perfect plan but navigation through a vast internal space of possible configurations, with feedback as the compass. The four-neuron Spark illustrates that intuition vividly, though it demonstrates rather than proves the link to biological brains.
